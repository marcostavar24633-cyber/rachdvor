РАЧНЫЙ ДВОР — документация сайта и Cloudflare Pages

СТРУКТУРА
- index.html — главная страница, каталог, корзина и форма заявки.
- catalog.html — каталог с поиском и фильтрацией.
- product.html — карточка товара.
- admin-login.html — вход администратора.
- admin.html — управление товарами и условиями магазина.
- admin-orders.html — список заявок и изменение статусов.
- data.json — резервные данные каталога.
- assets/raki/ — локальные фотографии проекта.
- functions/ — Cloudflare Pages Functions (серверный API).
- wrangler.toml — пример KV binding для локальной разработки/конфигурации.

КАК РАБОТАЕТ КАТАЛОГ
- Публичные страницы запрашивают GET /api/catalog.
- Если API или KV-каталог недоступен, страницы используют data.json как резерв.
- Администратор может менять товары и условия в admin.html и сохранять их через PUT /api/catalog.
- API принимает HTTPS-фотографии и безопасные относительные пути внутри assets/.
- Локальные пути вроде assets/raki/hero.png разрешены; абсолютные пути и попытки выхода из assets/ запрещены.
- Для серверной публикации каталога необходима авторизованная сессия и KV binding ORDERS_KV.

ЗАЯВКИ
- POST /api/order проверяет данные и состав заказа по актуальному каталогу.
- Honeypot отсекает часть автоматических отправок.
- При настроенном ORDERS_KV заявка сохраняется на 90 дней.
- Лимит отправки — до 8 заявок с одного IP за час (KV-счётчик).
- Если KV не подключён, API возвращает ошибку и не сообщает, что заявка сохранена.
- Если заданы TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID, API отправляет уведомление в Telegram. Без этих переменных заявка всё равно может сохраниться, но уведомление не отправляется.

АДМИНИСТРИРОВАНИЕ И ЗАЩИТА
- POST /api/admin-login проверяет ADMIN_PASSWORD и выдаёт подписанную HMAC-сессию.
- SESSION_SECRET должен содержать не менее 32 символов.
- Сессионная cookie: HttpOnly, Secure, SameSite=Strict, срок действия — 8 часов.
- Для входа требуется ORDERS_KV; ограничение попыток входа — 8 попыток на IP за 15 минут.
- Middleware защищает /admin.html, /admin-orders.html, /api/orders и /api/order-status.
- PUT /api/catalog отдельно проверяет действующую администраторскую сессию.
- POST /api/admin-logout завершает сессию на стороне браузера, удаляя cookie.
- Cloudflare Access/Zero Trust можно использовать как дополнительный внешний уровень защиты, но он не заменяет серверную проверку сессии приложения.

УПРАВЛЕНИЕ ЗАЯВКАМИ
- GET /api/orders возвращает список заявок с постраничной загрузкой.
- PATCH /api/order-status меняет статус заявки.
- Допустимые статусы: Новый, Принят, Готовится, Выполнен, Отменён.
- Доступ к этим API разрешён только с действующей администраторской сессией.
- Для больших объёмов заявок может потребоваться отдельная индексация и дальнейшая оптимизация пагинации.

НАСТРОЙКИ CLOUDFLARE PAGES
В Pages project → Settings → Functions → Variables and Secrets задайте:
1. ADMIN_PASSWORD — длинный уникальный пароль администратора.
2. SESSION_SECRET — случайная секретная строка не короче 32 символов.
3. TELEGRAM_BOT_TOKEN — необязательно, токен Telegram-бота для уведомлений.
4. TELEGRAM_CHAT_ID — необязательно, ID чата для уведомлений.

В Pages project → Settings → Functions → KV namespace bindings добавьте:
- Binding name: ORDERS_KV
- Namespace: созданный KV namespace проекта.

Не публикуйте значения секретов в GitHub, HTML или клиентском JavaScript. Не используйте буквальный placeholder из wrangler.toml как реальный ID namespace.

ПЕРЕД КОММЕРЧЕСКИМ ЗАПУСКОМ
- Подтвердить ассортимент, цены, размеры/калибр, состав и наличие.
- Подтвердить контакты, город, самовывоз, доставку и способы оплаты.
- Убедиться, что есть права на коммерческое использование фотографий.
- Проверить в целевом Cloudflare Pages проекте KV binding, секреты, вход администратора, сохранение каталога, тестовую заявку, её появление в админке и смену статуса.
- Отдельно проверить получение Telegram-уведомлений, если интеграция включена.
- Проверить сайт на телефонах и компьютерах.

ПУБЛИКАЦИЯ
Изменения в репозитории проходят GitHub Actions validation и preview-сборку Cloudflare Pages, если она подключена к репозиторию. Production-публикация выполняется по настройкам интеграции ветки main. Ручной Cloudflare deploy не выполняется без отдельного разрешения.

ОГРАНИЧЕНИЯ ПРОВЕРОК
Статическая проверка JavaScript/JSON не заменяет тестирование реальных API, KV, секретов, Telegram и пользовательских сценариев в целевом Cloudflare аккаунте. Не считайте приём заявок готовым к работе, пока эти сценарии не проверены на production-конфигурации.
