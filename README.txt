РАЧНЫЙ ДВОР — Cloudflare Pages Functions: приём заявок

Основные файлы:
- index.html — главная страница, корзина и форма заявки
- catalog.html — каталог с поиском и фильтрацией из data.json
- product.html — универсальная карточка товара
- admin.html — локальная панель управления
- data.json — каталог и условия
- functions/api/order.js — серверная проверка и приём заявок
- wrangler.toml — пример привязки KV для Cloudflare
- logo.svg, favicon.svg — фирменная графика

Что делает endpoint:
- принимает POST /api/order
- проверяет формат, контакт и состав корзины
- отсекает заполненную скрытую honeypot-ловушку
- ограничивает до 8 заявок с одного IP за час при включённом KV
- сохраняет заявки в KV на 90 дней, если привязка ORDERS_KV настроена
- без KV НЕ заявляет, что заказ сохранён

Обязательная настройка Cloudflare:
1. В Cloudflare Dashboard откройте Workers & Pages → KV и создайте namespace, например ORDERS_KV.
2. В настройках Pages-проекта → Settings → Functions → KV namespace bindings добавьте binding name ORDERS_KV и выберите созданный namespace.
3. Не вставляйте буквальный REPLACE_WITH... из wrangler.toml; это шаблон. При настройке через Dashboard используйте реальный namespace binding.
4. Разместите папку functions рядом с index.html в корне проекта и повторно задеплойте.
5. Отправьте тестовую заявку и проверьте запись в KV.

Важно:
- Сейчас сервер принимает и сохраняет заказ, но автоматическая отправка уведомления продавцу ещё не настроена. Для этого отдельно подключается email/Telegram/CRM через секреты и интеграцию.
- Для защиты admin.html используйте Cloudflare Access (Zero Trust) или исключите admin.html из публичной сборки. Клиентский пароль в HTML не является защитой.
- Панель admin.html пока локальная: редактирует данные в браузере и экспортирует data.json. Это не полноценная серверная CMS.
- До публикации замените демо-фотографии, заполните настоящие цены, контакты и условия.


УПРАВЛЕНИЕ ЗАКАЗАМИ (новый модуль)
- admin-orders.html — защищённая страница просмотра заказов и смены статусов.
- functions/api/orders.js — GET /api/orders, выдаёт последние заказы.
- functions/api/order-status.js — PATCH /api/order-status, меняет статус.
- functions/_lib/admin-auth.js — общая серверная проверка доступа.
- Новые заказы получают статус «Новый».
- Статусы: Новый, Принят, Готовится, Выполнен, Отменён.

ОБЯЗАТЕЛЬНАЯ ЗАЩИТА АДМИНКИ
1. В Cloudflare Zero Trust создайте Access Application типа Self-hosted для домена сайта.
2. Защитите как минимум пути:
   - /admin-orders.html
   - /api/orders
   - /api/order-status
   Также защитите /admin.html или удалите его из публичной сборки.
3. Создайте политику Allow только для своего адреса электронной почты. Не делайте публичное исключение для API.
4. В Pages project → Settings → Variables and Secrets добавьте переменную ADMIN_EMAIL со своим email (обычная переменная, без кавычек).
5. Убедитесь, что привязка KV namespace с именем ORDERS_KV настроена в Pages Functions.
6. Повторно разверните сайт. Войдите через Access и откройте /admin-orders.html.
7. Создайте тестовую заявку на сайте, затем проверьте, что она появилась в админке и статус сохраняется.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
- Заголовок Cf-Access-Authenticated-User-Email считается доверенным только если Cloudflare Access действительно защищает указанные пути. Не публикуйте API без Access.
- Список показывает до 100 заказов за один запрос; API сканирует до 1000 ключей KV. Для большого потока заказов понадобится пагинация/индекс.
- При смене статуса срок хранения записи устанавливается ещё на 90 дней.
- Автоматические email/Telegram уведомления, выгрузка заказов и полноценный аудит действий пока не реализованы.
- Этот пакет подготовлен локально; он не развёрнут в вашем Cloudflare аккаунте и не прошёл live-проверку.
